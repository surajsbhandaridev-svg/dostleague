# DostLeague v9: social games implementation report

## Validation status (read first)
**Not run:** `npm install`, backend/frontend builds, Vitest suites, Playwright, any browser, any socket or database flow. The sandbox has no network.
**Run for real (plain Node, compiled with `tsc`):** all 13 cover SVGs parse as XML with no external URLs; catalogue-vs-backend cross-check (0 mismatches); BotBrain accuracy per question type and difficulty; the Signal Saboteur engine over 3,600 simulated games (all finished, 0 private-info leaks, input validation, scan and self-vote rules). Everything else below is written but unverified.

## Implemented
- **Art + catalogue:** 13 original local SVG covers in `frontend/public/games/` (generated by `tools/make-covers.py`, ≤2.4 KB each). Single metadata source `frontend/src/games.ts` (id, title, category, image, alt, modes, players, ranked, botSupport, routes). Cards: 16:9 cover, title, category, mode badges, keyboard/focus support, lazy loading, per-game local fallback (own colours + glyph) if an image fails.
- **Discovery:** 7 filters (only games that truly support the mode), a mode-chooser dialog with only real modes (no disabled buttons), difficulty chips, Escape to close.
- **Solo practice (unranked, repeatable):** Quick Trivia, Emoji Puzzle, Guessing Challenge, Pattern, Memory, Math Rush, Odd One Out, Word Scramble via `/practice/:mode`; mixed Practice at `/practice`. Daily Dangal rules are unchanged and practice never consumes the ranked attempt (separate endpoints and state).
- **Solo vs bots (same 8 modes):** `/practice/:mode?bots=3&difficulty=…`. `backend/src/botbrain.ts`: seeded RNG, easy/medium/hard profiles (accuracy ≈0.6/0.8/0.94 measured, response windows 6–13.5 s / 3.5–9.5 s / 1.8–6.5 s), separate solvers per question type (arithmetic, letters, number patterns, group lookup, imperfect memory recall, local knowledge table). Bots receive only `{type,prompt,options}`. Same scoring rule as humans. Standings with BOT labels are shown during and after the game. Completed human results are saved in `solo_game_results` for personal history after migration `007_accounts_and_solo_results.sql` is applied and the database is reachable. Bot opponents are not real users and bot matches do not enter the ranked public leaderboard.
- **Signal Saboteur (solo vs 3–7 bots, 4–8 players):** `backend/src/saboteur.ts` + `/api/saboteur/*` + `/saboteur`. Phases: briefing, clue (≤40 chars, validated), discussion with public-info bot reactions, one-time Signal Scan (letter-count band only), private vote (no self-vote), resolve. Tie or wrong majority = failed round; two failed rounds = Saboteur wins; if caught, the Saboteur gets one guess at the secret among category words (steals the win if right). Four bot personas (analytical, cautious, bold, bluffer); bots use only their own prompt plus the public board; noise and mistake rates by difficulty. Human can be Saboteur or Signal Team. Never stalls: bots act instantly when the human acts.
- **Backend consistency:** `backend/src/modes.ts` (`ROOM_MODES`, `SOLO_MODES`) feeds the socket enum and the practice schema; `modes.xcheck.test.ts` checks the frontend catalogue against them.

## Not implemented (honest list)
1. **Bots inside friend rooms / "fill empty seats" / bot difficulty in the lobby / "humans only" toggle / start-with-bots.** Not built. Friend rooms are human-only, as before.
2. **Signal Saboteur with friends (real-time room)** and discussion timers/reaction chips. Solo vs bots only.
3. **Persistence of solo/bot/Saboteur results** and a bot-summary table. No new migration was added; these sessions are in memory (lost on server restart) and unranked. Nothing existing was changed in the database.
4. Solo mode for Community Challenges and Caption Battle (they need real players or approved content).
5. Configurable question counts (fixed at 5) and per-player practice progress history.
6. Trivia/emoji/riddle bots use a local table built from the handwritten bank, so unknown or new questions fall back to guessing. Bot accuracy there is easy/hard ≈ 0.6/0.94 by construction.
7. No tests were added for socket flows; Saboteur REST endpoints have no supertest coverage (engine unit tests exist).
